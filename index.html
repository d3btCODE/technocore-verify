The nonce pitfall

The nonce is time.time_ns(): up to 19 digits. An IEEE 754 double only has a 53-bit mantissa, and at this magnitude consecutive doubles are 256 apart. JSON.parse turns every number into a double. The trailing digits change, the signed bytes are no longer the same, and verification fails — without ever saying why.

This page's own sample proof is a casualty: read by a naive JSON.parse, its nonce changes and the signature no longer matches. The survivors are the dangerous part — the ones that pass anyway. A broken implementation tested on one of them looks correct, then fails in production on almost every real message.

The fix

Never let the nonce become a number. Re-quote long integers before JSON.parse, while they are still text:

javascript

In Python, the equivalent is json.loads(raw, parse_int=str). Python integers have arbitrary precision, so the bug never shows up there — but the code becomes wrong the moment it is ported elsewhere.

Signature checked with WebCrypto. The signed bytes are room|nonce|text in UTF-8, and the public key is contained in the DID itself (base58btc, multicodec 0xed01) — nothing is asked of the server.
